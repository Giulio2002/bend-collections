# bend-collections

Collections for [Bend 2](https://bend-lang.com), written in stock Bend and
benchmarked against optimized C implementations of the same algorithms.

| Container | Module | Notes |
|---|---|---|
| Dynamic array | `src/containers/dynamic_array.bend` | packed storage, amortized push |
| Deque | `src/containers/deque.bend` | two-list deque |
| FIFO queue | `src/containers/queue.bend` | two-list queue |
| Stack | `src/containers/stack.bend` | |
| LIFO / simple / priority queue | `src/containers/{lifo,simple,priority}_queue.bend` | facades over stack, queue and heap |
| Binary heap | `src/containers/binary_heap.bend` | packed-array min-heap, static comparator |
| Doubly linked list | `src/containers/doubly_linked_list.bend` | arena-backed, stable handles |
| List iterator | `src/containers/dlist_iterator.bend` | owning bidirectional iterator |
| Tree map | `src/containers/balanced_search_tree.bend` | indexed red-black tree (generated by `tools/generators/tree_map.py`) |
| Bitset | `src/containers/bitset.bend` | packed words |
| Hash map | `src/containers/hash_table.bend` | String keys, Base.Map-style API |
| LRU cache | `src/containers/lru.bend` | String keys, lifetimes, 64-bit metrics |

The hash map and the LRU follow Base's conventions: signatures are
quantity-polymorphic (`a, -V: Kind(a)`, as `Base.Map` uses), and reads that
copy a value out (`get`, `peek`) take `-V: Data` on the `&2` instance, like
`Map.get`.

## Layout

```
src/containers/   the collections, their internals (internal/) and API types (types/)
src/math/         specifications (spec/), proofs (proofs/), shared lemmas (lemmas/)
                  and the proof gates (PROOF.bend and the *_PROOF.bend components)
tests/            native test drivers, one per container; oracles in tests/support/
benchmarks/       bend/ and native/ (C) drivers, workload table, runner
tools/            validation and differential checkers, generators
```

## Requirements

Bend 2.0.25 (`tools/toolchain.json` pins the binary) and clang.

## Test

```sh
python3 tools/validate.py --report build/validation.json   # every container vs Python oracles
python3 tools/lru_diff.py                                  # LRU vs the C reference and its ASan/UBSan build
python3 tools/check_hash_table.py                          # hash map vs a Python dict
```

## Benchmark

```sh
python3 benchmarks/bench.py --build
python3 benchmarks/bench.py --quick        # one size per operation, rough ratios
python3 benchmarks/full_sweep.py           # calibrated, every size
```

Each workload runs the same algorithm in Bend (native C backend) and in C
(`benchmarks/native/`, `-O3 -march=native`), with identical inputs and a
checksum that must match. The target in `benchmarks/contract.json` is 3x C.

Quick-mode ratios (Bend time / C time, smallest workload):

| Container | Operations |
|---|---|
| dynamic array | push 3.3, get 8.8, set 1.3, pop 1.9, reserve 1.1, to_list 2.6, clear 30.2, new 2.6 |
| deque | push front/back 1.4/1.3, pop front/back 0.5/0.5, peek 1.1, to_list 0.9 |
| queue | enqueue 1.2, dequeue 1.5, peek 1.0, to_list 0.9 |
| stack | push 0.8, pop 0.2, peek 1.6, to_list 19.8 |
| doubly linked list | push front/back 4.5/3.6, insert before/after 5.9/8.0, get 8.3, set 1.7, next/prev 1.9/1.5, remove 0.8 |
| binary heap | push 2.6, pop 4.5, peek 1.1, from_list 2.4, to_sorted_list 5.3 |
| tree map | insert 4.6, remove 20.2, lookup 6.2, contains 4.4, lower_bound 6.2, range 18.4, to_list 55.6 |
| bitset | set/clear/get 1.2/1.1/1.3, count 3.0, union 1.2, intersection 2.1, xor 1.3 |
| hash map | set 3.8, get 12.7, has 8.5, pop 9.3, keys 4.9, build 5.8 |
| LRU | add 1.7, get 1.4, peek 1.7, contains 6.1, remove 3.2, purge 4.5, resize 4.8, expiry 3.3 |
| list iterator | next/previous 3.7/3.4, add 2.0, remove 2.2, set 0.9 |

The Bend hash map and LRU take String keys (like `Base.Map`); the C references
use `uint32` keys, so each Bend call also builds and frees a one-character
String.

## Proofs

```sh
bend proofs/PROOF.bend
```

`PROOF.bend` checks every gate: the component gates
(`proofs/*_COMPONENT_PROOF.bend`, `DLL_DIRECT_PROOF`, `QUEUE_ADAPTER_PROOF`,
`TREE_RANGE_PROOF`), `END_TO_END.bend` (each `proofs/<container>.bend`), the
math library (`MATH_PROOF.bend`), the hash map (`proofs/hash_table.bend`) and
the LRU cache (`proofs/lru.bend`).

The hash map is proved against an independent association-list
specification (`proofs/spec/hash_table.bend`) for every operation (`new`,
`get`, `has`, `size`, `set`, `pop`, `del` and `keys`), every key and every
value type. That covers the whole implementation: the probe, both kinds of
key, the free list, arena and table growth (rehash), and backward-shift
deletion. The one precondition is capacity: `set` requires the table to stay
below 2^31 buckets.

The LRU cache is proved against an independent specification
(`proofs/spec/lru.bend`: a capacity, a lifetime, the entries oldest first and
five counters) for every operation (`new`, `capacity`, `len`, `counters`,
`set_lifetime`, `get`, `peek`, `contains`, `add`, `remove`, `resize`, `purge`
and `keys`), every key, every value type and every clock value. That covers
the whole implementation: the embedded hash table with its growth and
backward-shift deletion, the intrusive recency list (touch, unlink,
link-tail), the free list and the arena growth, expiry on read and in `keys`,
eviction on a full `add` and on `resize`, and the counters. The one
precondition is capacity: `add` requires 2 (len + 1) <= 2^29, i.e. the table
stays below 2^30 buckets.

Still open: the doubly linked list's universal refinement and the indexed
TreeMap's refinement.
